# 1. Модель угроз

**Модель угроз** - структурированное описание того, как может быть нарушена безопасность вашей системы, какие последствия это может повлечь и какие меры защиты необходимы

## Основные компоненты

- Угрозы
- Атаки
- Последствия

## Основные этапы построения модели

1. Определение границ и характеристик системы
2. Выявление возможных негативных последствий
3. Определение объектов воздействия
4. Определение источников угроз и модели нарушителей
5. Определение способов реализации угроз
6. Построение сценариев реализации угроз
7. Определение актуальных угроз и оформление отчета

## Подходы к созданию моделей

- Сратифицированный анализ - система как отдельные слои
- Сценарный подход - что если..?
- Анализ уязвимостей - пытаться выявить уязвимости на ранних стадиях
- SWOT-анализ - сильные и слабые стороны, возможности и угрозы

## Классификация угроз

- По уровню воздействия:
  - критический - ддос, кража данных
  - значительный - ВПО, фишинг
  - минимальный - ошибки конфигурации, слабые пароли
- По субъекту (кто осуществляет атаку):
  - внешние - злоумышленники, вымогатели
  - внутренние - сотрудник компании
  - физические - доступ к серверам
- По вектору атаки:
  - сетевые - сниффинг, ддос
  - прикладные - RSE, SQLi, XSS, CSRF
  - пользовательские - фишинг, соц. инженерия
  - физические - доступ к серверу
- По времени:
  - постоянная - RCE в zeroday варианте, фишинг, сниффинг, соц. инженерия
  - временная - периоды (например, ддос)

## Основные модели угроз

|Модель|Описание|Применение|
|---|---|---|
|PDR|Традиционная модель защиты|Защита критической инфраструктуры|
|CIA-Triad model|Конфеденциальность, целостность, доступность|Классификация требований безопасности|
|Stratisified Threat Model|Разделение по уровням системы|Сложные сети и приложения|
|MITRE ATT&CK|Глобальная база тактик атак|Анализ методов злоумышленников|
|NIST SP 800-30|Federal Risk Assessment Guide|Государственные стандарты США|
|ISO 27005/27019|Международные стандарты по рискам|Глобальная защита данных|

## Методы оценки рисков

### Денежная
$R=T \times V \times C$

R (risk) - риск
T (threat) - вероятность реализации угрозы
V (vulnerability) - уровень уязвимости системы
C (consequence) - возможный ущерб от инцидента

### Матрица рисков (квалификационная)
Оценка происходит по осям: вероятность \times воздействие
Результаты закрашиваются цветом:
- зеленая зона - мониторинг
- желтая зона - планирование действий
- красная зона - немедленные меры

### Qualitative Risk Assessment (качественная)

- Оценка экспертами
- Delphi - метод (анонимный опрос мнений от экспертов)
- Мозговой штурм

### Qualitative Risk Assessment (количественная)

- Численная оценка в денежном эквиваленте
- Монте-Карло
- Анализ деревьев отказов

### FMEA (Falure Mode & Effects Analysis)
- Анализ последствий отказов компонента
- Встроен в многие системы проектирования

## Качественная оценка рисков

Качественная оценка рисков - процесс определения уровня риска с использованием экспертных суждений, опыта и классификационных шкал вместо точных числовых расчётов.

- Оценка экспертами - сбор мнения специалистов с опытом в ИБ

Техники проведения:

-------
- Delphi-метод
  
Анонимный многоэтапный процесс сбор мнений от экспертов с обратной связью до достижения консенсуса.

Преимущества дельфи-метода:
1. Анонимность - снижает влияние авторитета экспертов друг на друга
2. Конструктивный диалог - каждый может аргументировать мнение
3. Стабильность - достигается консенсус через есколько раундов

Этапы:
1. подбор группы экспертов (7-15 человек)
2. Анонимное распределение вопросов по каждому риску
3. Сбор ответов через опросники/формуляры
4. Агрегация и анализ ресурсов
5. Обратная связь с аргументацией экспертов
6. Повторный раунд до стабилизации мнений

-------

- Индивидуальная консультация экспертов
- Групповые обсуждения с модерацией

Применение: нет достаточных исторических данных

Плюсы: быстро, учитывает интуицию и опыт

Минусы: субъективность, влияние личных мнений

## Количественная оценка рисков
Процесс оценки рисков с использованием численных значений, часто в денежном выражении. требует исторических данных и статического анализа.
- численная оценка в денежном эквиваленте: риск = вероятность на потенциальный ущерб

$R = P\times C$ - вероятность на потенциальный ущерб = риск

-----

- Анализ деревьев отказов

1. Определить нежелательное событие (топ-события)
2. Выбрать оновные пути к этому событию
3. Добавить промежуточные события (AND, OR, XOR-гейты)
4. Заполнить листинг базовых событий
5. Рассчитать вероятность каждого сценария

-----

- Анализ Monte-Carlo - статистический метод моделирования с использованием множества случайных вариаций параметров для прогнозирования диапазона возможных результатов

1. Определяем распределения вероятностей для каждого параметра - нормальное распределение ($\mu = 0.2,\ \sigma = 0.1$)
2. генерируем тысячи сценариев
3. суммируем результаты для каждого сценария
4. строим распределение итоговых рисков

Проводится 10000 симуляций -> получается диапазон возможных потерь.

- FMEA - метод анализа потенциальных модификаций отказа и их воздействия на систему или процесс. широко используется в проектировании оборудования и ПО.

Основные элементы:
- субъект (сервер, приложение, человек)
- режим отказа (авария, ошибка конфигурации)
- воздействие (последствия отказа на систему в целом)

Основные этапы:
1. Идентификация системы и компонентов
2. Определение режимов отказа (Modes)
3. Оценка последствий (Effects)
4. Ранжирование и приоритизация

::: warning Практический пример анализа
Объект: интернет-магазин одежды с онлайн-оплатой

|Действие|Результат|
|---|---|
|1. Идентификация активов|БД пользователей, платежный шлюз, сервер приложений|
|2. Выявление угроз|Фишинг, DDoS, SQL-инъекция, утечки данных|
|3. Оценка уязвимостей|Недостаточное шифрование, открытый порт, слабые пароли|
|4. Расчет рисков|$R = T \times V \times C$ для каждого сценария|
|5. Разработка контрмер|Шифрование, MFA, WAF, обучение персонала|
:::

## Пример расчёта риска для платежной системы
- угроза: кража данных при перехвате транзакции
  
$T = 0,4\times 70\% = 0,28$ - вероятность перехвата через уязвимость API

$V = 0,5$ - парольная аутентификация

$C = \$ 5000000$ - потери клиентов + штрафы за потерю данных
